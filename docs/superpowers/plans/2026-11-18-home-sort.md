# Home Repository Sorting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the home page's Repos view, the owner picks how repositories are sorted (views in the last 14 days, stars, forks, last activity, name), and the choice stays in the URL as `?sort=`.

**Architecture:** The server builds one sort-key record per repository: views come from D1 in one chunked query, and the other keys come from the repository list the App already returns. A client component reads `?sort` with nuqs and reorders the server-rendered cards without fetching again. A native `<select>` in the dashboard header changes the parameter.

**Tech Stack:** Next.js 15.5 App Router on Cloudflare Workers (OpenNext), D1 + Drizzle, nuqs (new dependency, per `.claude/rules/libraries.md` "URL state"), Vitest, Playwright.

**Spec:** none (small change; the owner chose the options on 2026-11-18: views in 14 days, stars, forks, last activity, name; stored in the URL).

## Global Constraints

- Sort values in the URL: `views`, `stars`, `forks`, `activity`, `name`. The default (no or unknown `?sort`) is `stars`, the current order.
- `views`: sum of `views.total` for the last 14 UTC days including today, from D1, one `inArray` query in chunks of at most 90 ids (as `lib/db/traffic.ts` does). No extra GitHub calls on the home page (Workers Free: 50 subrequests).
- `stars`, `forks`, `activity` sort descending (most first, newest `pushed_at` first); `name` sorts ascending, case-insensitive (`localeCompare` with `sensitivity: "base"`). Ties fall back to `name`.
- Changing the sort does not refetch data or reload the page, and it keeps `?view=`.
- The Owners view stays as it is.
- Labels in English (the app is English): "Sort by", "Views (14d)", "Stars", "Forks", "Last activity", "Name".

## Review Focus

- `?sort=bogus` or a missing sort: stars order, no error.
- A repository with no stored views: sorts as 0 views, not first or last by accident.
- A D1 read failure on the home page: the grid still renders, and views count as 0 (logged).
- Switching Repos/Owners after choosing a sort keeps `?sort`, and switching sort keeps `?view`.
- The sort `<select>` has a visible label (axe passes in the e2e fixture).
