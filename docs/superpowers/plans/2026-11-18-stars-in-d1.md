# Star History in D1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The daily job stores each repository's star history in D1, and the dashboard pages read stars from D1 instead of paging GitHub on every visit.

**Architecture:** A new D1 table `stars` holds new stars per repository per day. The daily job (`lib/update-traffic.ts`) pages `GET /repos/{owner}/{repo}/stargazers/history` for every installed repository and upserts the days. `/[owner]/[repo]` and `/[owner]` build their cumulative star series from D1. The total star count stays live from repo info. `/api/svg` and `/star-history` stay live from GitHub, because they serve any public repository, not only installed ones.

**Tech Stack:** Next.js 15.5 on Cloudflare Workers (OpenNext), D1 + Drizzle, Octokit App, Vitest, Playwright.

**Spec:** /Users/dvasyliev/Projects/forks/repohistory/docs/superpowers/specs/2026-11-17-cloudflare-migration-design.md (the migration spec this extends; the owner approved storing stars in D1 on 2026-11-18 to cut subrequests on `/[owner]` from ~43 to ~5).

## Global Constraints

- Workers Free: 50 subrequests and 10 ms CPU per request. D1: at most 100 bound parameters per statement.
- Every D1 query filters by `repo_id`; owner pages query with `inArray` in chunks of at most 90 ids (as `lib/db/traffic.ts` does).
- Dates are stored as `YYYY-MM-DD` text.
- Writes are idempotent upserts (`onConflictDoUpdate` on the primary key), at most 20 rows per statement (as `lib/traffic-rows.ts` does).
- The GitHub App stays read-only; star history uses `GET /repos/{owner}/{repo}/stargazers/history` (Metadata: read), `per_page` 30, until a short page, at most 100 pages.
- `RepoStarsData` keeps its shape; `totalStars` comes from the caller's live `stargazersCount`.

## Review Focus

- A repository with stars on GitHub but no rows in D1 yet (before the first job run): the page shows the live total and an empty chart, not a crash.
- A repository with zero stars: the job writes nothing, and the chart is empty.
- A star-history request that fails for one repository in the job: logged with the repo name, and traffic for that repository and the other repositories is still saved.
- A day that GitHub later reports with a different count: the upsert replaces the stored count.
- `/api/svg` for a repository that is not installed: still draws from live GitHub, unchanged.
